# ExhibitOS public demo

This repository builds the approved reference exhibition for demo.exhibitos.org. The locked output includes the Viewer, cover, Studio entry and existing editor assets.

Use Node 24.21.0, npm 11.19.0 and Git. Run `node build.mjs` from a fresh checkout. The build fetches the pinned public Platform commit and, for a static-input release, the pinned demo content commit. It verifies the complete static-input inventory and copies the approved output; deploy and preview preparation install the pinned Platform dependencies without lifecycle scripts for Wrangler. Older native-closure releases use Platform's reference demo build. It verifies the exact output file inventory and SHA-256 digests before placing the site in `dist-demo`. Serve that directory as the preview root.

The lock records the source and toolchain, publication revision, public index and manifest, and all approved output digests. A content or shared dependency update requires an explicit lock update and verification. Deployment configuration is managed separately.

Platform source is available at [ExhibitOS/platform](https://github.com/ExhibitOS/platform) under AGPL-3.0-or-later. The build carries through the pinned publication rights records and generated third-party notices. Those records govern the individual assets.

## Cloudflare non-production preview

Delivery configures the approved isolated Worker before running these commands. Use the dedicated `DEMO_PREVIEW_NAME=verify-ba66d909`, its corresponding `DEMO_PREVIEW_WORKER` named `exhibitos-<preview name>-preview`, the existing parent's immutable `DEMO_PREVIEW_WORKER_ID`, and `CLOUDFLARE_ACCOUNT_ID`. Supply the approved `CLOUDFLARE_API_TOKEN` through provider secrets for the preview command. If the provider exposes the secret to both phases, unset it in the build shell before running npm or the build. The Worker must have an approved preview URL and scope, with no production routes or bindings.

Use `node build.mjs --prepare-preview` as the build command and `node preview.mjs` as the preview command in the same fresh workspace. Set `DEMO_PREVIEW_SOURCE_COMMIT` to the full reviewed Demo SHA. The build rejects a different checkout before fetching Platform or installing dependencies. The build installs the Platform lock once and retains its Wrangler 4.147.0 in ignored local tooling. The preview verifies the same `dist-demo` again, writes a one-use config and calls only Wrangler Preview. No second build or additional dependency installation is needed.

The two preflight reads confirm the Worker ID and the absence of the Preview name at the time of the reads. They do not provide atomic create-only enforcement. Delivery must confirm explicit authorization for the dedicated nonce parent, retain its creation receipt and control all writers for the target through the single attempt. The preview rechecks the parent's immutable ID before upload. Keep the build and preview receipts on failure. If the connection or upload result is missing, uncertain or unexpected, stop and reconcile the exact build and Preview records without a retry or fallback. Delivery can remove its own Preview after verifying the exact account, Worker and Preview name. Discard the isolated workspace when its receipts are retained. Production settings and rollback are managed separately.

## Cloudflare production deployment

Cloudflare Workers Builds watches `main` in `ExhibitOS/demo` for the existing `exhibitos-viewer-demo` Worker. The production trigger is configured to start a build on pushes to `main`. Update the approved index in Workers Builds alongside an approved content pin change so the deploy command can verify the new output. In the same fresh workspace, set the build command to `env -u CLOUDFLARE_API_TOKEN node build.mjs --prepare-deploy` and the deploy command to `node deploy.mjs`. Use the pinned Node and npm versions above. If a token is available to both phases, unset it in the build shell before invoking npm or the build.

Set `CLOUDFLARE_ACCOUNT_ID`, the existing Worker's immutable `DEMO_DEPLOY_WORKER_ID`, and the approved `CLOUDFLARE_API_TOKEN` for the deploy phase. Set `EXHIBITOS_APPROVED_DEMO_INDEX_SHA256` to the independently approved public index digest. It must match both the lock and the verified output. Deployment checks the existing Worker identity and verifies the built `dist-demo` against the lock before invoking the Wrangler installed by the build. Workers Builds must provide the branch and checkout commit. The deploy command checks the current remote main before validation and again before upload, and skips superseded builds. The tracked configuration uses the existing static asset routing policy.
